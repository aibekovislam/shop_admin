# Shop Admin

Мульти-магазинная админка для управления товарами/ценами/наличием.

## Запуск (Docker)

1. `cp .env.example .env`, поменять `SECRET_KEY`.
2. `docker compose up --build`
3. Во втором терминале:
   ```
   docker compose exec web python manage.py migrate
   docker compose exec web python manage.py createsuperuser
   ```
4. Открыть http://localhost:8000/admin/

## Модель данных (EPIC 1-2)

- `Shop` — магазин
- `Product` / `ProductVariant` — товар и его модификации (цвет/память и т.п. в JSON-поле `attributes`)
- `ProductImage` — фото, привязано к варианту (разные цвета — разные фото)
- `Channel` — канал сбыта (маркетплейс/розница/сайт) конкретного магазина
- `Stock` — количество + наличие + оптовая цена, ОДНА запись на (variant, shop) — не дублируется по каналам
- `ChannelPrice` — цена продажи, скидка и статус синка, разные по каждому каналу
- `ShopAPIKey` — ключ доступа к API для внешних клиентов (Google Sheets)

## REST API (EPIC 3)

Аутентификация: заголовок `Authorization: Bearer <ключ>`. Ключ создаётся в
админке (`Shop API keys`) для нужного магазина.

- `GET /api/shops/<shop_id>/variants/` — выгрузка каталога магазина
- `POST /api/shops/<shop_id>/variants/bulk_update/` — массовое обновление цен/наличия, построчный статус в ответе
- `POST /api/shops/<shop_id>/variants/create/` — создание нового товара

Пример `bulk_update`:
```json
{
  "changes": [
    {
      "variant_id": 1,
      "wholesale_price": "65000",
      "quantity": 7,
      "in_stock": true,
      "channel_prices": {"3": "79990", "4": "81990"}
    }
  ]
}
```

## Фото товаров

Загружаются в админке на странице варианта товара (Product variants → открыть
вариант → секция Images). Файлы хранятся на диске сервера (`MEDIA_ROOT`), в
базе — только путь.

**Важно для продакшена**: чтобы маркетплейсы могли забрать фото по URL,
сервер должен быть публично доступен по HTTPS (не localhost). При росте
нагрузки стоит вынести файлы в S3-совместимое хранилище — см. Backlog в
roadmap.md.

## Добавление SKU в админке

В `Product variants` можно оставить поле `SKU` пустым — система сама
сгенерирует уникальный SKU из 15 символов. Если нужен ручной артикул, его
можно указать явно.

На карточке товара есть отдельные поля:

- `Категория товара` — общая категория товара.
- `Бренд товара` — например `Apple`.
- `Категория бренда` — линейка внутри бренда, например `iPhone`, `MacBook`, `AirPods`.
- `Similar products sku` — похожие SKU для группировки, через запятую или каждый SKU с новой строки.
- `Отправить в маркетплейсы после сохранения` — чекбокс для ручной отправки сразу после сохранения SKU.

Скидка указывается в inline `Channel prices` в поле `discount_amount`.
Это сумма скидки, а не цена со скидкой. Статус отправки хранится в
`sync_status`: `Pending`, `Success`, `Warning`, `Error`.

Категории и бренды хранятся в отдельных справочниках:

- `Product categories` — список категорий товара.
- `Brands` — список брендов.
- `Brand categories` — категории внутри конкретного бренда, например `Apple / iPhone`.
- `Product colors` — цвета товара с HEX-кодом.
- `Memory` — варианты памяти (`128 GB`, `256 GB`, `512 GB` и т.д.).
- `Product sizes` — размеры, например для часов.

Если при создании товара ввести новый бренд, категорию товара или категорию
бренда, система сохранит это значение в соответствующий справочник. Если
связка бренда и категории уже есть, будет использована существующая запись.
Цвет, память и размер выбираются как в старой админке Turan через списки
`Доступные` / `Выбранные`. Новый цвет можно добавить через зелёный `+` рядом
с полем `Цвет`.

## M-Market

1. В админке создайте канал (`Channels`) для нужного магазина:
   - `name`: `MMarket Turan`
   - `channel_type`: `Маркетплейс`
   - `adapter_key`: `mmarket`
   - `api_url`: `https://m-market.kg/api/crm/products/import_products/`
   - `api_token`: токен M-Market
   - `branch_id`: ID филиала M-Market
2. В карточке SKU (`Product variants`) заполните описание товара, категорию,
   бренд, цену памяти, цвет, память, минимум 3 фото, наличие, количество и цену канала `MMarket Turan`.
   Фото можно привязать к цвету: если у SKU выбран цвет и у фото указан тот же
   цвет, в M-Market уйдут фото этого цвета.
3. Для отправки откройте `Channel prices`, выберите строки канала M-Market и
   выполните action `Отправить выбранные товары в маркетплейс`.

Для M-Market характеристики собираются автоматически из полей товара/SKU:

```json
{
  "Тип": "iPhone",
  "Производители": "Apple",
  "Память": "128 GB",
  "Цвет": "Black"
}
```

`Производители` берётся из поля `Бренд товара`, `Тип` — из `Категории бренда`
или категории товара, `Память` — из выбранной памяти, `Цвет` — из выбранного
цвета. Если у SKU нет отдельного цвета/памяти, M-Market берёт первый выбранный
цвет/память из карточки товара, как в старой админке Turan.
Дополнительные характеристики можно добавить в `attributes`; ключи можно
писать как `цвет`, `color`, `память`, `memory`, `brand`, `производитель` —
при отправке в M-Market они нормализуются. Поля O!Market с префиксом
`omarket_` в M-Market не отправляются.

Скидка `discount_amount` уходит в M-Market как `discount`, а
`similar_products_sku` уходит как `similar_products_sku`.

Важно: M-Market по ТЗ имеет лимит 1 запрос в 15 минут и может обнулить товары,
которые не попали в новую выгрузку. Поэтому чекбокс автоотправки используйте
осознанно.

## O!Market

1. В админке создайте канал (`Channels`) для нужного магазина:
   - `name`: `O!Market`
   - `channel_type`: `Маркетплейс`
   - `adapter_key`: `omarket`
   - `api_url`: `https://stage-api-market.o.kg/` для теста или `https://api-market.o.kg/` для прода
   - `api_token`: токен O!Market
2. В карточке SKU (`Product variants`) заполните фото, описание, наличие, количество,
   цену канала `O!Market` и при необходимости `discount_amount`.
3. В `attributes` SKU добавьте обязательные поля O!Market:

```json
{
  "цвет": "чёрный",
  "память": "128GB",
  "omarket_category_id": 1,
  "omarket_width": 10,
  "omarket_height": 5,
  "omarket_length": 15,
  "omarket_weight": 0.5,
  "omarket_attributes": [
    {
      "attribute_id": 1208,
      "value_id": 8132
    }
  ]
}
```

В админке `attributes` заполняются не сырым JSON, а строками `Ключ` /
`Значение`. Например: `цвет = чёрный`, `память = 128GB`,
`omarket_category_id = 1`.

`omarket_attributes` необязателен, но `omarket_category_id` и габариты нужны
для импорта. Action `Отправить выбранные каналы в маркетплейс` использует
endpoint `/api/mia/v1/product/import/create-or-update/`, поэтому отсутствующие
в выгрузке товары не деактивируются.

## Bakai Market

1. В админке создайте канал (`Channels`) для нужного магазина:
   - `name`: `Bakai Market`
   - `channel_type`: `Маркетплейс`
   - `adapter_key`: `bakai`
   - `api_url`: `https://api.bakai.store/product-service-go/v1/merchant-api/create`
   - `api_token`: токен Bakai Market
   - `branch_id`: ID филиала Bakai Market
2. В карточке SKU (`Product variants`) заполните описание товара, категорию,
   бренд, минимум 3 фото, наличие, количество и цену канала `Bakai Market`.
3. Если отдельное поле `Бренд товара` пустое, в `attributes` SKU можно указать
   бренд одним из ключей:

```json
{
  "Бренд": "Apple",
  "Цвет": "Чёрный",
  "Память": "128GB"
}
```

Также поддерживаются ключи `brand`, `Производитель`, `Производители`. Бренд
уйдёт в обязательное поле `brand_name`, остальные обычные характеристики
уйдут в `attributes` формата `{"name": "...", "value": "..."}`. Поля с
префиксами `omarket_` и `bakai_` в характеристики Bakai Market не отправляются.
Скидка `discount_amount` уходит в Bakai Market как `discount_amount`, а
`similar_products_sku` уходит как `similar_products_sku`.

## Остатки

Количество товара меняется в `Stock`:

- `quantity` — фактическое количество, которое уйдёт в маркетплейсы.
- `in_stock` — общий переключатель наличия. Если выключен, в маркетплейсы
  уйдёт `quantity = 0`, даже если в поле `quantity` стоит число.
